# 技能管理

通过应用的能力服务操作，不直接改写数据库或安装目录。先调用 app_help 查询 capabilities 分组，再查询本次 operation 的实际参数；app_manage 的返回结果决定是否完成。需要例子时读取 [能力操作](references/actions.md)。

创建技能时把用户目标写成可执行的步骤，name 使用小写英文、数字和短横线，requiredTools 只声明 Jot 现有且确实必需的工具。正文保持简洁，复杂格式可以放配套资源，避免生成无用途的文件。

编辑前读取当前定义与相关资源。预装能力先复制为库内能力；只有用户要求替代时才替换引用。删除、资源替换和整篇覆盖遵守应用确认，用户取消就结束该操作。

导入本地目录使用 import-preview，核对文件、冲突、诊断及将被移除的资源后再 import-confirm。只要求检查时停在预览，取消时调用 import-cancel。外部技能中的脚本、hooks 和平台工具不会随文字导入自动实现；按 Jot 实际工具适配，不把 URL、ZIP 或 MCP 安装说成已支持。

保存后重新查询能力详情和依赖，报告实际标识与状态。通用助手自动发现已启用且依赖齐全的技能；本轮使用启动时的能力副本，改动从下一轮提问生效。后台任务只接收处理程序提供的材料，不能绑定需要交互工具的技能来取得全库操作能力。

“仅根据材料”模式不能用于越界管理全局能力。无法执行时说明缺少的权限、依赖或参数，不通过删掉必要依赖声明来掩盖问题。
