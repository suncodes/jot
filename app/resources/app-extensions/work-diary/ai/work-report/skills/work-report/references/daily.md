# 日报

默认以“今日计划、今日进展、明日计划、今日 OKR 总结”四部分组织；用户指定格式优先。以当前日草稿为主题依据，工程日志补充具体动作、验证和结果。没有实质草稿时说明缺口；若用户明确提供工程日志或 @ 材料作为替代，可据实整理，不为了填模板编造工作。

今日进展按工作主线组织，支持动作并入对应主线，保留材料中有依据的数量、对象与范围。每项先说今天实际取得的结果，再写关键动作、证据和对交付的作用。真实联调、发布和业务数据验证与编译、静态检查分开表达；仅有方案就写方案，不提升完成等级。

用户提到昨晚、跨天、补昨天工作时，按连续事项读取昨天的正式日报及两天的相关日志。只把昨天未覆盖、且今天形成明确后续结果的事实归入今天；已汇报内容仅作必要背景。日期归属不确定时说明或询问，不把跨天时间戳自动当作今日成果。

当月 OKR 以草稿中的实际 O／K 为准，对相关项写真实支持进展，不硬凑每项。明日计划来自明确待办和未完成事项；今日计划不能从实际完成结果倒推。无需强制每条都添加风险或业务价值，材料不足就省略，不凭空写数字和百分比。

从 prepare 返回的 days[0].draftPath 读取当天草稿，months 中对应月份的 draftOkrPath 提供原始目标；正式日报仍写 prepare.path。工程日志只从已配置来源及用户补充材料中寻找，缺少时说明覆盖范围。
