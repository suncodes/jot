# 工作日记与工作报告

工作日记用于快速打开当天草稿并在需要时初始化月份目录；工作报告技能根据材料生成日报、周报、月报或 OKR 进展。它们与时间线的日总结是不同场景。

## 配置一次

在“设置 → 应用插件”安装或启用工作日记，选择 `content/` 下自己的工作根目录。例如 `content/工作/工作记录`，不是固定的本机磁盘地址。可配置：

- 草稿月份目录，例如 `草稿/{{yyyy}}年{{MM}}月`。
- 正式报告月份目录，例如 `AI总结/{{yyyy}}年{{MM}}月`。
- 日报草稿文件名，例如 `{{yyyy}}-{{MM}}-{{dd}}.md`。
- 草稿、OKR 模板，以及可选的工程日志目录。

工作根目录和配置可以建立多个入口，各入口独立。配套工作报告 AI 包可在安装时选择，也可以之后安装；它并非打开草稿的必要条件。

## 每日记录

点击工作日记快捷入口：如果当前草稿月目录存在，直接继续打开或创建当日草稿；如果不存在，补齐该月的草稿及四类报告目录，可按配置初始化 OKR。不会预创建整个月的日报文件。

同一天已有草稿就打开原文件，不覆盖。工程日志是可选证据来源，不配置就不自动猜测扫描目录。

## 生成正式报告

在助手通过 `$` 或 `/` 选择“工作总结”，说明报告类型和日期。技能读取本次类型的配套规则，先计算实际路径，再查找和分段读取草稿、工程日志与已有正式报告。

日报以草稿主题为主，工程日志补充依据；周月报优先综合已有正式报告。计划、实现、验证和发布需要区分，文件修改时间不能直接证明当天完成了某项工作。

用户要求生成或更新正式报告时，使用工作报告操作直接保存正式目标，可以覆盖原报告，无需再次把草稿作为预览提交。正式文件保留普通相对来源链接，原草稿不随之改写。技能会回读需要核对的内容；实际失败不会标成已保存。

不用应用插件也可向技能明确提供路径规则。限定材料时遵守 `@` 和“仅根据材料”的范围；来源不足会说明缺口，不会为了填满模板编造成果。
